# Starter teams by target

These are starting points. Fit every team to the specific target, then run the checks in SKILL.md.

| Target | Starter team |
|---|---|
| Startup pitch deck | Skeptical investor doing diligence, competitor's strategist, target customer, technical due-diligence reviewer, logic checker |
| Business plan or strategy | Competitor's strategist, finance reviewer who rebuilds the numbers, operator who must execute it, target customer, logic checker |
| Software product or app | First-time user, power user, interaction designer, QA engineer hunting edge cases, plain-language editor |
| Technical design | Site reliability engineer, security reviewer, engineer who will maintain it, QA engineer hunting edge cases |
| Written report or memo | Hostile reader, fact checker, domain expert, logic checker |
| Video, ad or creative | Target viewer who scrolls away fast, skeptical viewer, craft critic, retention or conversion specialist |
| Website or landing page | Target customer, conversion specialist, accessibility reviewer, competitor's marketer, plain-language editor |
| Policy or process | Person looking for loopholes, frontline person who must follow it, compliance reviewer, affected customer or member |
| Contract or proposal | Counterparty's lawyer, delivery lead, finance reviewer, logic checker |
| Research or analysis | Methods reviewer, replication-minded skeptic, domain expert, decision-maker who will act on it |

Each attacker needs an attack method, not only a job title. Examples:

- Walk the real path from start to finish and record every failure.
- Rebuild the numbers from the inputs.
- Try the edge cases: empty, huge, wrong, repeated, interrupted.
- Assume the conclusion is false and trace which claim fails first.
- Act as the competitor and plan the response.
- Search for a loophole or an abuse path.
